3 Approaches to Clean Bookmarks

Pick the architecture that fits best — or mix elements

A

Extension-Only (No Backend)

Pure browser extension. Checks URLs directly from the browser. No server to host or maintain.

Pros

  • Zero infrastructure cost
  • Instant publish to extension stores
  • User data never leaves their browser
  • Works offline (for local checks)

Cons

  • CORS blocks many sites from extensions
  • No fallback for blocked URLs
  • Limited concurrency in browser
B

Extension + Optional Proxy ⭐ Recommended

Extension tries in-browser first. For blocked/CORS-failing URLs, falls back to a lightweight proxy service. Proxy can be self-hosted or use a free tier.

Pros

  • Works without proxy for most URLs
  • Proxy handles the hard cases (CORS, firewalls)
  • Users can bring their own proxy
  • Graceful degradation if proxy is down
  • Privacy-respecting by default

Cons

  • Proxy needs hosting (small cost)
  • Slightly more complex architecture
C

Extension + Required Backend

All URL checking goes through your server. Extension is a thin UI. Backend handles all requests, rate limiting, caching.

Pros

  • Most reliable URL checking
  • Can cache results across users
  • Centralized rate limit management
  • Best for scale

Cons

  • All user bookmarks go through your server (privacy concern)
  • Ongoing hosting cost required
  • Extension useless if server is down
  • More complex to build and operate
