Architecture Overview

Does this structure make sense for what you have in mind?

Extension Components

Popup UI

Control Panel

Toolbar button → opens panel. Shows scan progress, then results grouped by category. Select/deselect per group. One "Zap" button.

Background Service Worker

URL Checker

Reads bookmarks via chrome.bookmarks API. Sends HEAD requests with smart concurrency. Classifies results. Survives popup close.

Browser API

Bookmarks Access

Native bookmarks permission gives read + delete access to all bookmarks. No HTML import needed — works directly with live browser data.

Storage

Scan Cache

Results cached locally so you don't re-scan everything every time. Cache expires after X days (configurable, default 7).

Data Flow

Click toolbar icon
→ Background worker reads all bookmarks from browser
→ Queue URLs with per-domain rate limiting (default: 3 concurrent, 1 req/domain/sec)
→ HEAD request → follow redirects → classify result
→ Stream results live to popup as they come in
→ Show categorized results (Dead / Moved / Unreachable)
→ User selects what to delete → confirm → chrome.bookmarks.remove()

Browser Support

Uses WebExtensions API — supported natively by Chrome, Firefox, Edge. Safari requires Xcode + Apple developer account to package, but same codebase works. One codebase, 4 browsers.
